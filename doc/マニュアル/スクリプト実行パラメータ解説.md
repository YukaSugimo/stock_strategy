## backtest.py — バックテスト実行

### 概要

watchlist.csv の全銘柄に対して、指定した戦略・期間でバックテストを実行する。
結果は `data/backtest_results.csv` と `data/backtest_summary.json` に保存される。

### 構文

```powershell
python scripts/backtest.py --strategy <戦略名> [オプション]
```

### パラメータ一覧

| パラメータ | 必須 | デフォルト | 説明 |
|-----------|------|-----------|------|
| `--strategy` | YES | なし | 使用する戦略名。`scripts/strategies/` 配下のファイル名（拡張子なし）を指定 |
| `--watchlist` | NO | `data/watchlist.csv` | 対象銘柄リストのCSVパス |
| `--days` | NO | `365` | バックテスト期間（日数）。大きいほど精度は上がるが時間がかかる |
| `--workers` | NO | `4` | 並列処理のワーカー数。CPUコア数-1 程度が目安 |
| `--resume` | NO | `false` | 前回中断したチェックポイントから再開する |
| `--chunk` | NO | `20` | 一度にメモリに乗せる銘柄数。メモリが少ない場合は小さくする |

### 実行例

```powershell
# 基本実行
python scripts/backtest.py --strategy s01_rsi_macd_bb

# 期間とワーカー数を指定
python scripts/backtest.py --strategy s01_rsi_macd_bb --days 365 --workers 4

# 短期間でざっくり確認したいとき
python scripts/backtest.py --strategy s01_rsi_macd_bb --days 90 --workers 1

# 途中で止まった場合に再開
python scripts/backtest.py --strategy s01_rsi_macd_bb --resume

# メモリが少ない環境向け
python scripts/backtest.py --strategy s01_rsi_macd_bb --days 365 --workers 2 --chunk 10
```

### 出力の見方

```
==================================================
  バックテスト完了
==================================================
  戦略           : s01_rsi_macd_bb
  対象銘柄数     : 94          # watchlistの銘柄数
  スキップ銘柄   : 1           # 上場廃止・取得不可でスキップした銘柄数
  取引発生銘柄   : 93          # 1件以上トレードが発生した銘柄数
  総トレード数   : 421         # 全銘柄合計のトレード件数
  勝率           : 34.9%       # 利益が出たトレードの割合
  平均損益率     : -0.94%      # 1トレードあたりの平均損益
  プロフィット   : 0.61        # PF（1.0以上で黒字、高いほど良い）
  結果内訳       : 利確=54  損切=211  タイムアウト=156
```

**PF（プロフィットファクター）の目安**

| PF | 評価 |
|----|------|
| 2.0以上 | 優秀 |
| 1.5以上 | 良好 |
| 1.2以上 | 使える |
| 1.0〜1.2 | 要改善 |
| 1.0未満 | 負けシステム |

## optimize.py — グリッドサーチ

### 概要

`params/{戦略名}_grid.yaml` に定義したパラメータの全組み合わせでバックテストを実行し、
最もPFが高いパラメータを探す。結果は `data/optimize_{戦略名}_{日時}.json` に保存される。

### 構文

```powershell
python scripts/optimize.py --strategy <戦略名> [オプション]
```

### パラメータ一覧

| パラメータ | 必須 | デフォルト | 説明 |
|-----------|------|-----------|------|
| `--strategy` | YES | なし | 使用する戦略名 |
| `--watchlist` | NO | `data/watchlist.csv` | 対象銘柄リストのCSVパス |
| `--days` | NO | `365` | バックテスト期間（日数） |
| `--workers` | NO | `4` | 並列処理のワーカー数 |

### 実行例

```powershell
# 基本実行
python scripts/optimize.py --strategy s01_rsi_macd_bb

# ワーカーを増やして高速化（メモリ・CPU に余裕がある場合）
python scripts/optimize.py --strategy s01_rsi_macd_bb --days 365 --workers 8
```

### 組み合わせ数の計算

`params/s01_rsi_macd_bb_grid.yaml` の例：

```yaml
rsi_buy_threshold:  [25, 30, 35, 40]   # 4通り
rsi_sell_threshold: [60, 65, 70, 75]   # 4通り
bb_std:             [1.5, 2.0, 2.5]    # 3通り
entry_condition:    ["2of3", "3of3"]   # 2通り
```

4 × 4 × 3 × 2 = **96通り** を全部試す。

### 出力の見方

```
==================================================
  グリッドサーチ完了
==================================================
  組み合わせ数: 96
  有効結果数 : 88

  上位5パラメータ（profit_factor順）:
    pf=1.23  win=45.0%  trades=120  | rsi_buy_threshold=35  bb_std=1.5  entry_condition=2of3
```

上位に出たパラメータを `params/{戦略名}.yaml` に反映して `backtest.py` で再検証する。

## workers の決め方

| 状況 | 推奨値 |
|------|--------|
| 動作確認・デバッグ | `--workers 1` |
| 通常実行 | `--workers 4` |
| メモリ・CPU に余裕あり | `--workers 8` |
| CPUコア数が多い場合 | コア数の半分〜2/3程度 |

workers を増やしすぎるとメモリ不足やyfinanceのレート制限にかかる場合がある。

## エラーが出たとき

ログファイルを確認する：

```powershell
cat logs\(Get-Date -Format "yyyyMMdd").log
```

| よくあるエラー | 原因 | 対処 |
|--------------|------|------|
| `SKIP` と表示される | 上場廃止・取得不可 | 自動スキップ済み。watchlist.csvから削除推奨 |
| `ERROR:データ不足` | 指定期間のデータが少ない | `--days` を短くするか銘柄を除外 |
| `ModuleNotFoundError` | ライブラリ未インストール | `pip install yfinance pandas pyyaml` |
| レート制限エラー | yfinanceへのアクセスが多すぎる | 30分待ってから再実行 |

# 運用マニュアル

## 毎日の操作フロー

```
データ取得 → 指標確認 → バックテスト → 結果分析 → 改善
```

### 1. データ取得

```powershell
cd "C:\Users\yuucy\OneDrive\デスクトップ\起業\claude_code\株分析ツール"
python scripts/fetch_data.py --days 60
```

初回は全銘柄を取得。DB実装後は差分のみ取得される。

### 2. 指標確認（任意）

特定銘柄のシグナルをすぐ確認したいとき。

```powershell
python scripts/indicators.py --ticker 7203.T
python scripts/indicators.py --ticker 7203.T --json
```

### 3. バックテスト実行

**現状（プラグイン構造改修前）:**

```powershell
# 現在のbacktest.py（戦略固定）
python scripts/backtest.py --days 365 --workers 4

# 途中から再開
python scripts/backtest.py --resume
```

**改修後（プラグイン構造実装後）:**

```powershell
# 単一戦略
python scripts/backtest.py --strategy s01_rsi_macd_bb --params params/s01_rsi_macd_bb.yaml --days 365 --workers 4

# 全戦略比較
python scripts/backtest.py --compare-all --days 365 --workers 4
```

### 4. グリッドサーチ（改修後）

```powershell
python scripts/optimize.py --strategy s01_rsi_macd_bb --grid params/s01_rsi_macd_bb_grid.yaml --days 365 --workers 4
```

### 5. 結果確認

```powershell
# サマリーを確認
cat data/backtest_summary.json

# 個別トレードを確認
cat data/backtest_results.csv
```

### PostgreSQLへの接続

```powershell
$env:PATH += ";C:\Program Files\PostgreSQL\18\bin"
psql -U postgres -p 1220 -h localhost -d stock_quant
```

### よく使うSQL

```sql
-- 全戦略の比較
SELECT s.name, su.win_rate, su.profit_factor, su.trade_count
FROM summaries su
JOIN runs r ON su.run_id = r.id
JOIN strategies s ON r.strategy_id = s.id
ORDER BY su.profit_factor DESC NULLS LAST;

-- 最近のバックテスト実行一覧
SELECT r.id, s.name, sv.version, r.days, r.created_at
FROM runs r
JOIN strategies s ON r.strategy_id = s.id
JOIN strategy_versions sv ON r.version_id = sv.id
ORDER BY r.created_at DESC
LIMIT 10;

-- 銘柄別の勝率
SELECT t.code, t.name,
       COUNT(*) AS trades,
       ROUND(AVG(CASE WHEN tr.result = 'take_profit' THEN 1.0 ELSE 0.0 END) * 100, 1) AS win_rate
FROM trades tr
JOIN tickers t ON tr.ticker_id = t.id
GROUP BY t.id, t.code, t.name
HAVING COUNT(*) >= 5
ORDER BY win_rate DESC;
```

## トラブルシューティング

### データ取得が失敗する

```powershell
# ログを確認
cat logs/$(Get-Date -Format "yyyyMMdd").log

# 個別銘柄で再試行
python scripts/fetch_data.py --tickers 7203.T --days 60
```

yfinanceのレート制限の場合は30分待ってから再実行。

### バックテストでエラーが出る

```powershell
# --workers 1 で並列処理を無効化してデバッグ
python scripts/backtest.py --days 30 --workers 1
```

### PostgreSQLに接続できない

```powershell
# サービス状態を確認
Get-Service -Name "postgresql-x64-18"

# 起動していなければ起動
Start-Service -Name "postgresql-x64-18"

# PATHが通っているか確認
psql --version
# 通っていなければ
$env:PATH += ";C:\Program Files\PostgreSQL\18\bin"
```

### UnicodeDecodeError が出る

`scripts/db.py` の `DB_CONFIG` に `"options": "-c client_encoding=UTF8"` が設定されているか確認。
スクリプト側の `open()` に `encoding="utf-8"` が指定されているか確認。

### データが30行未満エラー

```powershell
python scripts/fetch_data.py --tickers 7203.T --days 90
```

## ファイルバックアップ

DBはローカルのみなのでブレーカー等でデータが消えるリスクがある。
週1回程度、以下でバックアップを取る。

```powershell
# backupsフォルダを事前に作成しておくこと
mkdir backups

$date = Get-Date -Format "yyyyMMdd"
pg_dump -U postgres -p 1220 stock_quant > "backups/stock_quant_$date.sql"
```
